GitHub Actions cost calculator: how to estimate monthly runner spend

GitHub Actions cost depends on the runner type, how long each job is billed, how often the workflow runs, and how many jobs or matrix copies execute per run. For private repositories, standard hosted runners consume included minutes first and then use GitHub's standard per-minute pricing. Public repositories have different billing treatment for standard hosted runners.

Current baseline standard runner rates

RunnerBaseline rate
Linux 1-core (ubuntu-slim)$0.002/min
Linux 2-core x64$0.006/min
Linux 2-core arm64$0.005/min
Windows 2-core$0.010/min
macOS standard$0.062/min

GitHub bills hosted-runner job time in whole-minute units, so partial job minutes are rounded for billing. Larger runners have separate prices and should be modeled with their own SKU rate.

Monthly cost formula

monthly cost ≈ billed minutes/job × jobs/run × runs/day × 30 × runner rate

For a matrix build, jobs/run should include each expanded matrix copy. If a workflow has several independent jobs, estimate each job with its own runner and duration, then add them.

Example

A Linux 2-core job billed for 8 minutes, run 10 times per day with one copy, is approximately:

8 × 10 × 30 × $0.006 = $14.40/month

That is a variable runner estimate before considering included minutes, discounts, taxes, skipped jobs, conditional execution or other account-specific billing effects.

Why pull-request estimates are harder

Static YAML only tells part of the story. Real cost is affected by runtime history, workflow frequency, matrices, schedules, event duplication and whether newer pushes cancel obsolete runs. MinuteShield combines the workflow diff with recent history when GitHub permissions allow, then reports a before/after monthly delta directly on the pull request.

Important: a preventive estimate is not a GitHub invoice. Always treat included minutes, enterprise arrangements, larger-runner rules, self-hosted infrastructure and future pricing changes separately.
