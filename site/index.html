Security model

Analyze untrusted workflow changes without executing them.

The Action is designed around a narrow, review-focused trust boundary. Workflow YAML is fetched through GitHub APIs and parsed as data; policy is loaded from the trusted base revision.

FAQ

Questions engineering teams usually ask first.

MinuteShield produces preventive estimates, not invoices. Its job is to make likely cost impact reviewable before merge.

Does MinuteShield execute code from a pull request?

No. It fetches changed workflow YAML and parses it as data. The recommended integration uses pull_request, not pull_request_target.

How accurate are the cost estimates?

MinuteShield combines baseline GitHub-hosted runner pricing with workflow structure and recent history when available. Included plan minutes, conditional jobs, enterprise pricing, custom runners, dynamic matrices, and future pricing can make actual billed spend differ.

What happens when a new workflow has no reliable history?

It uses configured fallback runtime/frequency values and statically observable schedule information rather than treating tiny PR-generated history as representative production usage.

Can a pull request change its own allowed budget?

No. MinuteShield reads policy from the base branch, so the same pull request being evaluated cannot raise its own allowed monthly delta.

Can I pin the Action to an immutable version?

Yes. The recommended @v0 tag tracks compatible updates, while stricter environments can use the verified full commit SHA shown above.
