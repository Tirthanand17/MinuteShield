GitHub Actions macOS vs Linux: why runner choice changes CI cost

Runner operating system is one of the biggest direct inputs to hosted CI cost. GitHub's current baseline price for a standard Linux 2-core x64 runner is $0.006 per minute, while the standard macOS rate is $0.062 per minute.

Rate comparison

RunnerRate10 billed min × 100 runs
Linux 2-core x64$0.006/min$6.00
Windows 2-core$0.010/min$10.00
macOS standard$0.062/min$62.00

At those baseline rates, standard macOS is about 10.3× the per-minute price of standard 2-core Linux. That does not mean every macOS workflow should be moved: Apple-platform builds, Xcode, signing, simulator testing and macOS-specific behavior may genuinely require macOS.

Where waste usually appears

Cost risk increases when macOS is used for jobs that are not OS-dependent, when a large matrix repeats the same macOS work, or when every new pull-request push leaves older runs executing. Scheduled macOS jobs can also accumulate spend quickly if their frequency is higher than the value they deliver.

A safer optimization approach

  1. Keep Apple-specific build/test work on macOS.
  2. Move OS-independent linting, formatting, metadata checks and lightweight scripting to Linux where technically valid.
  3. Use matrix include/exclude rules so macOS only runs the combinations that matter.
  4. Add pull-request concurrency with cancellation so superseded runs stop.
  5. Use job timeouts to cap failure modes.
Do not optimize by price alone. A cheaper runner is only an improvement if it preserves the behavior the workflow is supposed to verify.
