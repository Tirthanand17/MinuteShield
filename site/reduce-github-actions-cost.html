How to reduce GitHub Actions cost without weakening CI

Good CI cost optimization removes duplicated or obsolete work rather than simply deleting useful tests. The safest improvements usually make workflows more targeted, bounded and aware of pull-request updates.

1. Cancel obsolete pull-request runs

When a developer pushes several commits to the same pull request, older workflow runs can keep using minutes even though only the newest commit matters. A PR-scoped concurrency group with cancel-in-progress: true can stop superseded runs.

concurrency:
  group: ci-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: true

2. Avoid duplicate event coverage

A workflow configured for both broad push and pull_request events can run twice for essentially the same change. Keep both only when they serve distinct purposes, and use branch/path filters when appropriate.

3. Put a ceiling on jobs

Use timeout-minutes so hung tests, stalled network calls or infrastructure problems cannot run indefinitely. Timeouts are both a reliability control and a cost boundary.

4. Keep matrices intentional

Matrices multiply cost. Before adding another language version, operating system or feature variant, decide whether every combination is needed on every pull request. Use include/exclude, targeted smoke coverage or less frequent full compatibility runs when that still meets the project's quality requirements.

5. Match the runner to the job

Use macOS or Windows where platform behavior is part of what you are validating. OS-independent checks can often run on Linux. Lightweight operations may be suitable for ubuntu-slim, but its environment and limitations differ from a full runner, so compatibility matters more than price.

6. Measure frequency and duration together

A two-minute workflow that runs hundreds of times can cost more than a 20-minute workflow that runs once per day. Look at both dimensions, plus matrix copies. For PR changes, compare the expected before/after monthly delta instead of evaluating a YAML line in isolation.

Optimization rule: remove work that is redundant, obsolete or over-broad; preserve work that protects correctness and release quality.
